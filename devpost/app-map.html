What the app is

A browser tower defense + clicker game: click the central castle for money, buy traps, place them on 4 paths, and upgrade the castle through 5 eras. It is one web page with no server. Two layers sit on top of each other and talk through one messenger:
World · Phaser 4

Map, castle, enemies, traps, waves. src/scenes/, src/world/, art drawn with code in src/art/.

Interface · HTML/CSS

Menu, HUD, Shop, picker, Upgrade button, results. src/ui/.

Rules · plain JS

Money, traps, damage, waves, upgrades — no Phaser, unit-tested. src/logic/, numbers in src/data/, tests in tests/.

Event bus

src/bus.js: the world says "state changed"; the interface says "buy this trap".

One action, end to end: clicking the castle

Reference route — follow it in your editor (search for the anchor text):

  1. src/scenes/GameScene.js → setupCastle()
    Phaser input: the castle image gets setInteractive with a round hit area, and castle.on('pointerdown', …) runs on every click. It calls the rule, shows popText, plays a squash tween, then emitState().
  2. src/logic/economy.js → clickCastle(state)
    The rule itself: adds the current era's clickMoney (from src/data/eras.js). No Phaser here, so tests/economy.test.js can check it directly.
  3. src/ui/hud.js → bus.on('state:changed'
    The interface hears the new state snapshot and updates the money pill (with a small bump animation). The HUD never touches Phaser; it only listens.

A practice to reuse

Keep the rules out of the engine and check them with small tests. In this build, all money, trap, wave, and upgrade rules live in src/logic/ as plain functions, tested in tests/*.test.js (33 tests). When the difficulty ramp changed after your first checkpoint, the test attacks from all 4 directions failed immediately: Wave 1 now had only 3 enemies. That failure showed the rule had changed rather than broken, so only the test's expectation needed updating — found in seconds, without playing a single wave.

On your next Phaser project: put game rules in plain modules, let scenes call them, and test the rules directly. Then use a quick scripted playthrough (like the 4× bot used for balancing here) for the parts tests can't judge — pacing and feel.
